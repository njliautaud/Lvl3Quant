# Task JSON Schema — HC #422 Persistent Task Queue

Every task is a single JSON object stored as one line in `queue.jsonl`.

## Required fields

| Field           | Type            | Notes                                                                 |
| --------------- | --------------- | --------------------------------------------------------------------- |
| `id`            | str (hex12)     | Globally unique. Generated by `enqueue.py` via `uuid4().hex[:12]`.    |
| `created`       | str (iso8601)   | UTC timestamp of enqueue.                                             |
| `command`       | str             | The exact shell command to invoke. No shell-escaping wizardry. Run via `bash -c`. |
| `priority`      | int (1..10)     | 1 = highest, 10 = lowest. Default 5.                                  |
| `status`        | str             | One of: `pending`, `claimed`, `running`, `done`, `failed`.            |

## Optional fields (all have defaults)

| Field             | Type                 | Default        | Notes                                                                                          |
| ----------------- | -------------------- | -------------- | ---------------------------------------------------------------------------------------------- |
| `created_by`      | str                  | hostname:script| Who enqueued.                                                                                  |
| `node_preference` | list[str]            | `["jupiter"]`  | Ordered preference. Empty list = any node. Members: `jupiter\|neptune\|saturn\|razer`.         |
| `gpu_required`    | bool                 | `false`        | Claim only succeeds if puller advertises `--has-gpu`.                                          |
| `working_dir`     | str                  | repo root      | `cd` here before invoking command.                                                             |
| `env`             | object               | `{}`           | Extra environment variables merged into child env.                                             |
| `max_runtime_s`   | int                  | `7200`         | Watchdog kills child after this many seconds. 0 = unlimited (NOT recommended).                |
| `depends_on`      | list[str]            | `[]`           | Task IDs that must reach `done` before this becomes claimable.                                 |
| `tags`            | list[str]            | `[]`           | Free-form labels for filtering / dashboards.                                                   |
| `notes`           | str                  | `""`           | Human-readable context. May be appended to on failure.                                         |
| `claimed_by`      | str / null           | null           | Filled by `claim.py`: `hostname:pid` of the claiming puller.                                   |
| `claimed_at`      | str (iso8601) / null | null           | When the task left `pending`.                                                                  |
| `started_at`      | str (iso8601) / null | null           | When the puller actually `Popen`'d the child.                                                  |
| `finished_at`     | str (iso8601) / null | null           | When `complete.py` ran.                                                                        |
| `exit_code`       | int / null           | null           | Process exit code.                                                                             |
| `log_path`        | str / null           | null           | Absolute path to combined stdout/stderr.                                                       |

## Lifecycle

```
pending --claim--> claimed --(puller exec)--> running --complete--> done
                                                              \--> failed
```

A claimed task whose sidecar `claimed/<id>.json` is older than `max_runtime_s + 600s`
and whose owning process is no longer running may be **released** back to `pending`
by an external reaper (NOT implemented in this scaffold; deferred to puller cron).

## Atomicity contract

All state transitions go through `fcntl.flock(LOCK_EX)` on `queue.lock`. The
queue file is rewritten atomically via `os.replace(tmp, queue.jsonl)`. Multiple
node pullers may race `claim.py` safely — exactly one will win each pending
task.
